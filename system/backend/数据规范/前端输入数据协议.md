# 前端输入数据协议（API 写入侧）

本文档定义前端可提交的数据类型、接口路径、字段格式与示例。  
统一前缀：`/api/v1`

## 1. 通用约定

- 时间字段使用 ISO 8601（UTC），示例：`2026-04-24T10:00:00Z`
- `Content-Type`：`application/json`
- 枚举值必须严格匹配（区分大小写）
- 数值字段支持整数/小数（后端会按 Decimal/Int 解析）

---

## 2. Admission 相关写入

### 2.1 新建入科

- **接口**：`POST /admissions`
- **用途**：创建 admission 并将床位标记为 occupied

请求体：

```json
{
  "admission_id": "ICU-ADM-0001",
  "patient_id": "pat1001",
  "bed_id": "B07",
  "admission_code": "A-20260424-001",
  "admit_time": "2026-04-24T10:00:00Z",
  "primary_diagnosis": "septic shock",
  "admission_reason": "persistent hypotension",
  "severity_on_admission": "critical",
  "attending_team": "ICU-A",
  "scenario_tag": "frontend"
}
```

字段约束：

- `severity_on_admission`：`stable | unstable | critical`
- `scenario_tag` 可选，默认 `custom`

### 2.2 更新入科状态

- **接口**：`PATCH /admissions/{admission_id}/status`
- **用途**：出科/转科/死亡/恢复 active

请求体：

```json
{
  "status": "discharged",
  "discharge_time": "2026-04-25T08:30:00Z"
}
```

字段约束：

- `status`：`active | discharged | expired | transferred`
- `discharge_time` 可为空

## 3. 事件写入（驱动六个 agent 联动）

### 3.1 Vital Sign 事件

- **接口**：`POST /admissions/{admission_id}/events/vital_sign`
- **触发链路**：`bedside_monitor -> patient_memory -> risk_sentinel -> clinical_summary -> ward_coordinator`（按条件触发）

请求体（可只传部分生命体征）：

```json
{
  "timestamp": "2026-04-24T10:05:00Z",
  "source": "monitor",
  "priority": "high",
  "heart_rate": 122,
  "mean_arterial_pressure": 58.2,
  "systolic_bp": 86,
  "diastolic_bp": 50,
  "respiratory_rate": 28,
  "temperature": 38.6,
  "spo2": 90.5,
  "fio2": 0.6,
  "pao2": 70.2,
  "aado2": 220.3,
  "ph": 7.31,
  "gcs": 13
}
```

字段约束：

- `source`：`monitor | lab | nurse | agent`（vital 常用 `monitor`）
- `priority`：`low | normal | high | critical`
- 体征字段全部可选（`null` 也可）

### 3.2 Lab 事件

- **接口**：`POST /admissions/{admission_id}/events/lab`
- **触发链路**：`patient_memory`，重要检验时进一步触发 `risk_sentinel/clinical_summary/ward_coordinator`

请求体：

```json
{
  "timestamp": "2026-04-24T10:10:00Z",
  "lab_type": "lactate",
  "value": 4.2,
  "unit": "mmol/L",
  "abnormal_flag": "high",
  "source": "lab",
  "priority": "high"
}
```

字段约束：

- `lab_type`：1-128 字符
- `unit`：1-64 字符
- `abnormal_flag`：`normal | high | low`
- `source` 默认 `lab`

### 3.3 Intervention 事件

- **接口**：`POST /admissions/{admission_id}/events/intervention`
- **触发链路**：`intervention_tracker -> patient_memory -> risk_sentinel -> clinical_summary -> ward_coordinator`（按条件触发）

请求体：

```json
{
  "timestamp": "2026-04-24T10:15:00Z",
  "intervention_type": "fluid",
  "description": "500ml crystalloid bolus",
  "dosage": 500,
  "unit": "ml",
  "source": "nurse",
  "priority": "normal"
}
```

字段约束：

- `intervention_type`：`fluid | vasopressor | ventilator_change`
- `description`：1-2000 字符
- `unit` 可为空，最大 64 字符
- `source` 默认 `nurse`

### 3.4 事件写入统一响应

三个事件接口都返回：

```json
{
  "event_id": "evt_xxx",
  "detail_id": "vit_xxx_or_lab_xxx_or_intv_xxx",
  "admission_id": "ICU-ADM-0001",
  "patient_id": "pat1001",
  "bed_id": "B07"
}
```

## 4. Orchestrator 写入

### 4.1 手动触发 demo-run

- **接口**：`POST /orchestrator/demo-run`
- **用途**：批量跑完整 pipeline（调试/演示）

请求体（两种模式）：

1) 全部 active admission：

```json
{
  "run_all_active": true,
  "memory_window_hours": 24,
  "top_k": 10
}
```

2) 指定单个 admission：

```json
{
  "admission_id": "ICU-ADM-0001",
  "run_all_active": false,
  "memory_window_hours": 24,
  "top_k": 10
}
```

字段约束：

- `memory_window_hours`：`1 ~ 72`
- `top_k`：`1 ~ 50`

### 4.2 手动触发 scheduler tick（可选）

- **接口**：`POST /orchestrator/scheduler/tick`
- **请求体**：无

## 6. Auto Demo 控制接口（`/demo/auto/*`）

用于“空医院起步 + 每步随机事件 + 每步 +5min”演示场景。

### 6.1 重置演示医院

- **接口**：`POST /demo/auto/reset`
- **请求体**：无
- **返回**：当前 demo 医院状态（sim_time/step_index/active_admissions 等）

### 6.2 执行下一步随机事件

- **接口**：`POST /demo/auto/next`
- **请求体**：无
- **返回**（核心）：
  - `step_index`
  - `sim_time_before`
  - `sim_time_after`
  - `event_type`（`admission_create | admission_discharge | vital_sign | lab | intervention`）
  - `event_request_payload`
  - `event_write_result`
  - `triggered_agents`
  - `db_effects`（本步新增 outputs/events/alerts/risks）
  - `agent_delta_summary`

返回示例：

```json
{
  "step_index": 12,
  "sim_time_before": "2026-04-24T10:55:00Z",
  "sim_time_after": "2026-04-24T11:00:00Z",
  "event_type": "intervention",
  "admission_id": "demo_adm_00004",
  "event_request_payload": {
    "timestamp": "2026-04-24T11:00:00Z",
    "intervention_type": "vasopressor",
    "description": "norepinephrine titration"
  },
  "event_write_result": {
    "event_id": "evt_xxx",
    "detail_id": "intv_xxx"
  },
  "db_effects": {
    "agent_outputs_added": 4,
    "agent_events_added": 9,
    "alerts_added": 1,
    "risks_added": 2
  },
  "agent_delta_summary": {
    "triggered_agent_names": ["intervention_tracker", "patient_memory", "risk_sentinel", "clinical_summary", "ward_coordinator"]
  }
}
```

### 6.3 查询当前状态

- **接口**：`GET /demo/auto/state`
- **返回**：`sim_time`、`step_index`、当前在院人数、占床数、最近事件

### 6.4 查询时间线

- **接口**：`GET /demo/auto/timeline?limit=100`
- **返回**：最近步骤明细列表（含 `payload/result`）
