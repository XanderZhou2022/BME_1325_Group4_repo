  - 从 `clinical_summary_router` 改为导出 `router`

### 3. 修复数据库连接与配置问题

定位到 `db-health` 500 的根因：

- PostgreSQL 鉴权失败：`fe_sendauth: no password supplied`
- `.env` 未按预期生效 / DSN 被默认值覆盖

处理方式：

1. 写入 `system/backend/api/.env`
2. 启动时显式设置环境变量：
   - `ICU_PG_DSN=dbname=icu_agent user=postgres password=123456 host=localhost port=5432`
   - `ICU_CORS_ORIGINS=*`
3. 用固定命令启动，避免错误 app：
   - `uvicorn --app-dir . app.main:app --host 0.0.0.0 --port 8000`

### 4. 端口与进程排障

对 8000 端口做了多次排查：

- 查占用进程
- 杀掉旧进程
- 重启正确后端服务
- 校验 `/health`、`/docs`、`/api/v1/ops/db-health`

确保外部访问到的是当前 ICU API，而非错误服务。

## 四、联调与局域网访问问题处理

### 1. 解决 `failed to fetch`

定位到常见跨机问题：前端默认 API 指向 `127.0.0.1`。在朋友电脑上会请求其本机，导致失败。

修复：

- `src/api.ts` 改为默认使用 `window.location.hostname` 拼接后端地址：
  - `http://{当前访问主机}:8000/api/v1`

### 2. 路径 404 问题

排查并确认：

- `/health` ok 但 `/api/v1/ops/db-health` not found 时，通常是起错 app 或错误目录启动
- 通过固定启动命令与目录（`--app-dir .`）彻底解决

### 3. 局域网访问验证

已确认：

- 朋友电脑可以访问后端健康接口
- 前端页面可跨设备访问
- API 调用可跨局域网成功返回
