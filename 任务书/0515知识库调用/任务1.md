# 任务书：Risk Sentinel Agent 与 Clinical Summary Agent 接入知识库和 LLM

## 一、总体目标

当前项目中已经存在 ICU 知识库，大约包含 175 张结构化 knowledge cards。每张 card 包含来源、domain、card_type、trigger_signals、related_risk_types、allowed_use、forbidden_use、evidence、human_review_required 等字段。

现在需要完成第一阶段的 **Knowledge-aware + LLM-assisted Agent Integration**，只接入两个 agent：

```text
1. Risk Sentinel Agent
2. Clinical Summary Agent
```

本阶段目标是：

```text
Risk Sentinel Agent：
在原有规则风险判断基础上，检索相关 ICU knowledge cards，并调用 LLM 生成保守、可审计的风险解释和升级理由。

Clinical Summary Agent：
整合 Bedside Monitor、Intervention Tracker、Risk Sentinel、Patient Memory 的结构化输出，检索相关 knowledge cards，并调用 LLM 生成 24h 查房摘要、problem list、watch items 和人工复核提醒。
```

重要原则：

```text
1. LLM 不直接判断风险。
2. LLM 不直接诊断。
3. LLM 不提出治疗建议。
4. LLM 不决定 ICU 收治、转出或资源分配。
5. 知识库只用于背景解释、摘要组织、风险提醒措辞和 human review 提醒。
6. 所有输出必须 human_review_required=true。
7. 所有 LLM 输入、输出和检索到的 cards 必须写入 audit log。
```

## 3.4 `retriever.py`

### 功能

实现 metadata-based retrieval。
第一版不要上复杂向量数据库。先做可控、可解释的规则检索。

### 函数签名

```python
def retrieve_cards(
    agent_name: str,
    patient_context: dict,
    risk_types: list[str] | None = None,
    trigger_signals: list[str] | None = None,
    query: str | None = None,
    top_k: int | None = None
) -> dict:
    ...
```

### 检索逻辑

先做 hard filter：

```text
1. card.human_review_required == true
2. agent_name in card.used_by_agents
3. card.domain in profile.allowed_domains
4. card.card_type in profile.allowed_card_types
```

然后做 scoring：

```text
+4：related_risk_types 与输入 risk_types 匹配
+3：trigger_signals 与输入 trigger_signals 匹配
+2：allowed_use 与 profile.allowed_use 有交集
+2：card_type 在当前 agent 高优先级 card_type 中
+1：query keyword 命中 card title / source_title / short quote / trigger_signals
-100：domain 不允许
-100：card_type 不允许
-100：agent 不在 used_by_agents
-100：human_review_required 不是 true
```

### 返回格式

```json
{
  "agent_name": "risk_sentinel",
  "query": "...",
  "risk_types": ["persistent_shock_risk"],
  "trigger_signals": ["persistent_hypotension", "limited_fluid_response"],
  "retrieved_cards": [
    {
      "card_id": "clinical_deterioration_012",
      "source_id": "...",
      "source_title": "...",
      "domain": "clinical_deterioration",
      "card_type": "deterioration_signal",
      "score": 9,
      "matched_fields": [
        "related_risk_types",
        "trigger_signals"
      ],
      "allowed_use": [
        "risk_explanation"
      ],
      "forbidden_use": [
        "diagnosis",
        "treatment_recommendation"
      ],
      "evidence": {
        "page": "...",
        "section": "...",
        "quote": "..."
      },
      "human_review_required": true
    }
  ],
  "safety_notice": "Knowledge cards provide background only and require human review."
}
```

## 5.2 不允许改掉原有 rules 逻辑

Risk Sentinel 原有规则逻辑必须继续作为主判断来源。

例如：

```text

```

这些风险是否触发，仍然由规则或结构化服务判断。
