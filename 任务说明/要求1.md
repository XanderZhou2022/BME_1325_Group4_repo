一、总任务概述
项目名称

最小可运行 Web 模拟医院 Demo

项目目标

开发一个 Web 端最小模拟医院 Demo，用于演示一个简化的医院就诊闭环流程。
本项目当前阶段的重点不是医疗智能推理，而是先把 医院场景、流程交互、前后端状态同步 跑通。

用户进入系统后，应能够完成以下最小流程：

进入医院 → 前往分诊室 → 与护士进行简短对话 → 被分配到医生诊室 → 与医生进行简短问诊 → 触发一次检查 → 查看检查结果 → 获得初步诊断与处方 → 前往药房 → 完成取药与本次就诊

当前阶段范围

本阶段只做一个 最小闭环 Demo，不做完整医院系统，不接入真实 agent API，也不做复杂医疗逻辑。

本阶段需要实现的内容

一个可视化医院主界面

一个可移动的患者角色

少量房间和 NPC

一个对话面板

一个病历/状态面板

一个由后端维护的 encounter 状态机

一个固定脚本/规则式 mock 对话流程

一组基础 API，用于前后端同步状态和消息

本阶段不需要实现的内容

真实 LLM / agent 对话

多科室复杂转诊

数据库持久化

复杂地图寻路

多患者并发

医疗决策真实性

用户系统/登录系统

权限系统

完整 EHR 系统

流程设计
1. 进入医院

用户打开页面，看到医院俯视图与患者角色。

2. 分诊

患者前往分诊室，与护士完成简短对话。
护士根据固定规则将患者分配到医生诊室。

3. 问诊

患者进入医生诊室，与医生完成简短问答。
医生触发一次 mock 检查。

4. 检查结果

系统返回写死的检查结果，并显示在右侧状态面板。

5. 诊断与处方

医生给出固定的初步诊断和处方建议。

6. 取药

患者进入药房，查看药品说明，完成本次就诊。

核心交付物

本项目最终应交付以下内容：

1. 可运行的前端 Demo

包含地图、角色移动、房间交互、对话面板、状态面板。

2. 可运行的后端服务

包含 encounter 创建、消息发送、状态获取、mock 对话、mock 检查结果等接口。

3. 前后端联调完成

前端可以通过后端接口完整跑通一次就诊流程。

核心设计原则
1. 先做闭环，再做复杂

优先保证“流程完整可演示”，而不是先做复杂功能。

2. 结构可扩展

虽然当前只用 mock 对话，但接口和状态设计要为后续接入 agent 留空间。

3. 前后端职责清晰

前端负责医院可视化、交互、界面状态呈现

后端负责 memory、对话记录、encounter 状态和 mock 响应逻辑

4. 尽量减少不必要复杂度

本阶段尽量避免“高级但没必要”的设计。
