二、前端任务概述
前端目标

前端负责构建整个医院可视化交互界面，使用户能够在网页中看到医院地图、控制患者进入不同房间、与 NPC 进行对话，并在侧边栏中查看病历状态、检查结果、诊断和处方。

前端的核心目标是：
把医院“做出来、动起来、连起来”。

技术栈

React

Phaser

TypeScript

可选：

Zustand 或 React Context 做全局状态管理

原生 CSS 或简单 UI 组件库

前端职责

前端只负责以下内容：

1. 医院地图展示

展示一个简化的医院平面图

包含大厅、分诊室、医生诊室、药房四个区域

每个区域有清晰标签

2. 角色与房间交互

展示患者角色

展示护士、医生、药师 NPC

支持点击房间或 NPC

支持患者移动到目标区域

到达目标区域后触发相应交互

3. 对话 UI

展示当前对话历史

展示系统消息

提供输入框或选项按钮

发送消息给后端

接收后端 mock 回复并渲染

4. 病历与状态 UI

展示患者基本信息

展示当前阶段

展示当前房间

展示检查结果

展示诊断结果

展示处方信息

5. 前后端联动

调用后端 API

管理 encounter 状态

在不同阶段更新 UI 和可交互对象

前端不负责的内容

前端当前不负责：

智能对话生成

医疗判断逻辑

消息推理

持久化存储

多 agent orchestration

数据库设计

前端需要完成的模块
1. 页面整体布局

实现一个三栏式或双栏式页面结构：

左侧或中间：医院地图区

右侧：病历/状态面板

下方或中间：对话面板

要求：

布局清晰

信息层次明确

适合演示

2. Phaser 医院地图模块

实现医院主场景，包含：

大厅

分诊室

医生诊室

药房

要求：

地图清晰

房间可区分

房间区域可以点击

当前房间可高亮

患者能在房间之间移动

可以先用简化矩形地图，不要求复杂美术资源。

3. 角色显示与交互

实现以下角色显示：

患者

护士

医生

药师

要求：

每个角色有固定位置

可以被点击

点击或进入对应区域后触发对话

4. 患者移动

实现最小患者移动逻辑：

点击房间后，患者平滑移动到目标点

到达目标点后更新当前 room

调用后端 /move 接口同步状态

当前不要求：

复杂寻路

碰撞系统

多角色同时移动

5. 对话面板

实现对话区域，支持：

展示历史消息列表

展示角色名

区分系统消息与角色消息

用户输入消息

点击按钮发送消息

接收后端返回消息

自动滚动到底部

支持两种最小模式之一：

输入框发送

选项按钮发送

建议优先做输入框 + 固定回复。

6. 状态面板

实现右侧病历/状态面板，显示：

患者姓名、年龄、性别

chief complaint

当前阶段

当前房间

分配科室

检查结果

初步诊断

处方信息

当前 encounter 状态

要求：

不同区域有标题

数据结构清晰

当后端状态变化时实时刷新

7. encounter 初始化与重置

前端需要支持：

页面加载时创建 encounter

拉取初始状态

拉取初始消息

提供“重新开始”按钮

重置后恢复到初始流程

8. API 调用封装

前端需要统一封装 API 调用逻辑，至少包括：

创建 encounter

获取 encounter 状态

获取消息历史

发送消息

更新房间

触发检查

完成流程

重置流程

前端核心状态

建议维护以下全局状态：

encounterId

currentRoom

stage

assignedDepartment

messages

labResults

diagnosis

prescription

patientPosition

status

前端交付标准

前端完成后，应满足以下标准：

1. 可以独立打开页面运行
2. 页面中可以看到医院地图与角色
3. 患者可以在房间之间移动
4. 可以与护士、医生、药师发生对话
5. 可以看到右侧状态变化
6. 可以完成一次完整就诊流程
7. 刷新或重置后可以重新开始
前端开发优先顺序
第一阶段

页面框架

医院地图

患者与 NPC

房间点击与移动

第二阶段

对话面板

状态面板

API 对接

第三阶段

联调

流程重置

UI 打磨

前端一句话任务说明

请实现一个 React + Phaser 的医院前端 Demo，重点完成地图、房间、角色、对话面板、状态面板和基础 API 联动，确保用户能在浏览器中跑通一次最小就诊流程。
