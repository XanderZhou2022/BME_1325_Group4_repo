# api调用测试 — 使用说明

本目录用于两件事：

1. **教学网 GenAI 网关**：直连校验 Key / 模型（`call_genai.py`）。
2. **ICU 多智能体后端**：与 `system/backend/api` 联调时的环境变量参考，以及 API 冒烟脚本。

仓库内路径：`BME_1325_Group4_repo/api调用测试/`（若你本地曾放在「远程连接配置」下，请以本仓库路径为准）。

---

## 一、安装依赖

在 **本目录** 下：

```powershell
cd "C:\Users\DELL\Desktop\icu\BME_1325_Group4_repo\api调用测试"
pip install -r requirements.txt
```

---

## 二、GenAI 网关（call_genai.py）

1. 复制 `.env.example` 为 `.env`，填入各模型的 `KEY_*`（勿提交 `.env`）。
2. 运行示例：

```powershell
python call_genai.py --profile deepseek_v32 --text "你好"
python call_genai.py --profile deepseek_v32 --text "你好" --no-stream
```

说明：

- 默认流式输出；需要完整 JSON 时加 `--no-stream`。
- `--profile`：`gpt52` | `deepseek_v32` | `deepseek_r1` | `qwen3` | `qwen_vl`。

---

## 三、后端 ICU Agent API 与 LLM 对齐

后端读取的是 **`system/backend/api/.env`**（前缀 `ICU_`，见 `app/config.py`）。

1. 参考同目录下的 **`backend.env.example`**，在 `system/backend/api/.env` 中配置：
   - `ICU_PG_DSN`：PostgreSQL 连接串。
   - **`deepseek_v32` 对齐方式**（与 `call_genai.py --profile deepseek_v32` 一致）：
     - `ICU_LLM_BASE_URL`：与 `api调用测试/.env` 里 `GENAI_API_URL` 一致（默认 `.../api/v1/start`）。
     - `ICU_LLM_API_KEY`：与 `KEY_DEEPSEEK_V32` 相同。
     - `ICU_LLM_MODEL`：与 `MODEL_DEEPSEEK_V32` 相同（示例中为 `deepseek-v3:671b`）。
   - `ICU_LLM_ENABLED=true`：启用后端内各 agent 的 LLM 结构化生成（Clinical Summary、Risk Sentinel 等）。
2. 若需先不连 LLM 冒烟，可临时设 **`ICU_LLM_ENABLED=false`**（走 fallback），网关确认无误后再改为 `true`。

启动后端（在 `system/backend/api`）：

```powershell
cd "C:\Users\DELL\Desktop\icu\BME_1325_Group4_repo\system\backend\api"
pip install -r requirements.txt
$env:ICU_CORS_ORIGINS="*"
uvicorn --app-dir . app.main:app --host 0.0.0.0 --port 8000
```

数据库需先按 `system/backend/测试数据库` 文档初始化（如 `init_core_tables.py` / `seed_test_data.py`）。

## 五、步进模拟（Agent + 知识库 + LLM/fallback）

仓库根目录下（需已启动后端、数据库可用）：

```powershell
cd "C:\Users\DELL\Desktop\icu\BME_1325_Group4_repo"
pip install requests
python system/simulation/run_simulation.py --reset --steps 5 --verbose-trace
```

可选参数：

- `--base-url`：默认 `http://localhost:8000/api/v1/demo/auto`。
- `--verbose-trace`：打印每步各 agent 的知识卡与 LLM/fallback 摘要。

说明：`/api/v1/*` 的 JSON 响应带合同信封，本脚本会自动解包 `data` 字段。

**为什么 Auto Demo 里点「Next Step」会很久？**

- 每一步会对**每位在院患者**顺序执行一条临床事件链（`dispatch_event_chain`），链上多个 Agent 会**同步**调用教学网关 LLM（如 `patient_memory`、`risk_sentinel`、`clinical_summary`、`ward_coordinator`）；大模型单次可达十余秒甚至更久。
- 整步在一个 **HTTP 请求 + 数据库事务** 内跑完，响应返回前浏览器**看不到**每个 Agent 的实时进度（不是页面卡死）。完成后可在 Showcase **Debug** 模式查看各子链的 `duration_ms` / `total_chain_ms`。
- 开发阶段若只想验证流程、不关心 LLM 文案，可在 `system/backend/api/.env` 设 **`ICU_LLM_ENABLED=false`**（走 fallback，会快很多）。
