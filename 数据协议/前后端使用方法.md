# ICU 项目前后端运行说明（Windows）

本文档用于指导你在本机完整启动 ICU 项目（PostgreSQL + 后端 FastAPI + 前端 React），并让局域网内其他电脑可以访问。

---

## 1. 环境准备

请先确认本机已安装：

1. PostgreSQL（建议 14+）
2. Python（建议 3.10+）
3. Node.js（建议 LTS）

快速检查：

```powershell
python --version
node -v
npm -v
```

---

## 2. PostgreSQL 启动与数据库准备

### 2.1 启动 PostgreSQL 服务

如果你通过安装器安装，通常服务名是 `postgresql-x64-xx`。可在“服务”里确认已运行。

### 2.2 创建数据库（首次）

使用 pgAdmin 或 psql 创建数据库：

- 数据库名：`icu_agent`
- 用户：`postgres`（或你的自定义用户）
- 密码：你安装时设置的密码

### 2.3 初始化核心表（首次或重置时）

在项目根目录执行：

```powershell
$env:ICU_PG_DSN="dbname=icu_agent user=postgres password=你的密码 host=localhost port=5432"
python "BME_1325_Group4_repo/system/backend/测试数据库/init_core_tables.py"
```

成功后会看到核心表（含 `agent_outputs`、`agent_events`、`orchestrator_runs` 等）创建完成。

## 3. 启动后端 FastAPI

### 3.1 安装后端依赖（首次）

```powershell
cd "C:/Users/DELL/Desktop/icu/BME_1325_Group4_repo/system/backend/api"
python -m pip install -r requirements.txt
```

### 3.2 正确启动命令（推荐固定使用）

> 必须在 `system/backend/api` 目录启动，并使用 `--app-dir .`，避免启动到错误 app。

```powershell
cd "C:/Users/DELL/Desktop/icu/BME_1325_Group4_repo/system/backend/api"
$env:ICU_PG_DSN="dbname=icu_agent user=postgres password=你的密码 host=localhost port=5432"
$env:ICU_CORS_ORIGINS="*"
uvicorn --app-dir . app.main:app --host 0.0.0.0 --port 8000
```

### 3.3 后端健康检查

浏览器打开：

- `http://127.0.0.1:8000/health`（应返回 `ok`）
- `http://127.0.0.1:8000/api/v1/ops/db-health`（应返回 status=ok）
- `http://127.0.0.1:8000/docs`（Swagger 文档）

如果 `db-health` 报 500，通常是数据库 DSN/密码错误。

## 5. 局域网其他电脑访问说明

### 5.1 朋友电脑先测后端连通

在朋友电脑浏览器测试：

- `http://你的本机IP:8000/health`
- `http://你的本机IP:8000/api/v1/ops/db-health`

都成功后，再打开前端：

- `http://你的本机IP:5173/`

### 5.2 防火墙放行

若局域网打不开，请在后端机器放行端口：

- TCP 8000（后端）
- TCP 5173（前端）

---

## 6. 推荐启动顺序（每次运行）

每次开机后，按这个顺序：

1. 启动 PostgreSQL 服务
2. 启动后端（`uvicorn --app-dir . app.main:app --host 0.0.0.0 --port 8000`）
3. 验证 `health` 与 `db-health`
4. 启动前端（`npm run dev`）
5. 用户端打开 `http://你的本机IP:5173/`

---

## 7. 常见问题排查

### 问题 A：前端显示 `Loading...` 或 `failed to fetch`

常见原因：

1. 后端没启动
2. 前端请求地址错误（例如请求到 `127.0.0.1`）
3. 防火墙阻断

处理：

- 先测 `http://你的本机IP:8000/api/v1/ops/db-health`
- 再看浏览器 Network 里失败请求 URL

### 问题 B：后端返回 404（尤其 `/api/v1/...`）

通常是启动了错误 app。请使用本文件第 3.2 的固定命令，并确保在正确目录。

### 问题 C：`db-health` 返回 500 / `fe_sendauth: no password supplied`

说明数据库连接字符串未正确传入。请检查：

- `$env:ICU_PG_DSN` 是否含 `password=...`
- DSN 是否完整（dbname/user/password/host/port）

### 问题 D：`table not found`

说明核心表未建全。重新执行：

```powershell
$env:ICU_PG_DSN="dbname=icu_agent user=postgres password=你的密码 host=localhost port=5432"
python "BME_1325_Group4_repo/system/backend/测试数据库/init_core_tables.py"
```

## 8. 一键联调建议（可选）

启动后可做一次最小联调：

1. 前端新增一个 admission
2. 提交 vital 与 intervention
3. 点击 `Run Full Pipeline`
4. 在患者详情页查看 risk / clinical summary
5. 在 DB Viewer 查看 `agent_outputs` 与 `agent_events`

如果以上都成功，说明系统闭环运行正常。
